计算机控制 · 视觉Computer Control · Vision

当一个界面没有 API、也没有可读的 HTML 时，GenericAgent 还能怎么操作它？答案是用眼睛看：截屏 → 识别出屏幕上的图标与文字 → 拿到它们的坐标 → 像人一样点过去。这一课讲 GA 的视觉链路。

🌍 宏观理解

视觉链路是一条流水线：截屏 → 检测 → 定位 → 行动。检测同时用上 YOLO（找图标这类视觉元素）和 OCR（认文字），输出一串带坐标的元素。拿到坐标后，就交给下一课的“鼠标键盘”去点、去敲。

  • UI 元素检测在 memory/ui_detect.py: detect()（YOLO + RapidOCR），返回 bbox / type（icon|text）/ label / confidence。
  • 纯文字识别在 memory/ocr_utils.py（本地 rapidocr）；远程桌面下用 ocr_window(hwnd) 避免黑屏。
  • 无文字图标可由视觉大模型保底：memory/vision_api.template.py；整套流程的要点见 memory/vision_sop.md。
  • 一个反复强调的坑：截屏分析后必须用物理坐标（与 ljqCtrl 一致）。

🧪 返回结构
memory/ui_detect.pydetect() → list[dict]
# 每个元素是一个 dict
{
  'bbox': [x1, y1, x2, y2],  # 物理像素框
  'type': 'icon' | 'text',  # YOLO 框=icon，OCR 框=text
  'label': str | None,  # 图标上若无文字则为 None
  'confidence': float
}
⚙️ match 模式怎么走

默认 mode='match'：先跑一次 YOLO 得到图标框，再跑一次全图 OCR，然后用 _iou()（交集占 OCR 框面积的比例）把文字“贴”到重叠的图标上当 label；没被任何图标匹配上的 OCR 框，单独作为 type='text' 元素输出。约 1.2s。

🔀 match vs crop

mode='crop' 改为把每个 YOLO 框 crop 出来垂直拼成一张长图（_ocr_crops_batch）只 OCR 一次，再按 y 坐标映射回各框——更精确但约 2.3s。日常用 match 即可，密集小图标识别不准时再换 crop。

2 OCR 的三个坑：ocr_utils.py 点击展开
⚠️ conf 与“无文字”

RapidOCR 有两个反直觉点，写在 ocr_utils.py 文件头：① 置信度是字符串（result[i][2] 是 str 不是 float，所以 _ocr_rapid 里要 float(r[2]) 转换）；② 无文字时返回 None 而不是空列表，必须先 if not result 兜底。

⚠️ 远程桌面黑屏

在 RDP 断开后，ImageGrab / mss 截到的是全黑图。解法是 ocr_window(hwnd)：它用 Win32 的 PrintWindow API 直接抓窗口位图，绕开屏幕缓冲，远程桌面下也能拿到画面。

🧪 三个入口

ocr_image(img) 认一张图、ocr_screen(bbox) 截屏区域再认、ocr_window(hwnd) 抓窗口再认；三者都返回 {text, lines, details}，details 里带 bbox 与 conf。

3 无文字图标怎么办？物理坐标与 VLM 保底 点击展开
⚠️ label=None 的元素

纯图标（如一个齿轮、一个箭头）没有文字，detect() 给它的 label=None。这时无法靠文字定位，可把该 bbox crop 出来交给视觉大模型识别语义——保底入口是 memory/vision_api.template.py: ask_vision(img, prompt)，支持 claude / openai / modelscope 三种后端。

❓ 为什么必须物理坐标

高 DPI 屏幕上“逻辑坐标”和“物理像素”不是一回事。截屏分析拿到的是物理像素框，而点击下一课用的 ljqCtrl 也按物理坐标算（内部再乘 dpi_scale），两端对齐才不会“看到的和点到的错位”。所以 ui_detect.py 一加载就打印“截图分析后必须使用物理坐标”。

⚙️ YOLO 跨进程缓存

加载 YOLO 权重很慢，所以 _yolo() 把推理外包给一个常驻 daemon：先 ping 127.0.0.1:31876，没起就 Popen 自己 --yolo-daemon 拉起来，之后每次检测走 HTTP 复用已加载的模型；daemon 不可用时回退 _yolo_local 本地推理。

🧩 生活类比
像给 Agent 装上一双眼睛加一根会指的手指：它看一眼屏幕，认出“那个蓝色的发送按钮在右下角”，然后把手指准确地点到那个像素位置。哪怕这个软件压根没有给程序留接口，它也能照用不误。
✅ 关键要点
  • 视觉链路：截屏 → 检测（YOLO+OCR）→ 定位 → 行动。
  • detect() 返回带坐标的元素；无文字图标可用 VLM 保底。
  • 始终使用物理坐标，远程桌面用 ocr_window 防黑屏。
💡 设计亮点
视觉是 GA 的“万能兜底”：API、HTML 都失效时，只要屏幕能显示，它就能操作。这把可控范围从“有接口的软件”一举扩展到“任何肉眼能用的界面”——也正因如此，GA 不必为每个 App 预置适配，看得见，就够了。

When an interface has no API and no readable HTML, how can GenericAgent still operate it? The answer is look at it: screenshot → recognize the icons and text on screen → get their coordinates → click there like a human. This lesson covers GA's vision pipeline.

🌍 The Big Picture

The vision pipeline is an assembly line: capture → detect → locate → act. Detection uses both YOLO (to find visual elements like icons) and OCR (to read text), emitting a list of elements with coordinates. With coordinates in hand, the next lesson's "mouse & keyboard" does the clicking and typing.

🔬 In the Source
  • UI element detection is in memory/ui_detect.py: detect() (YOLO + RapidOCR), returning bbox / type (icon|text) / label / confidence.
  • Plain text recognition is in memory/ocr_utils.py (local rapidocr); under remote desktop use ocr_window(hwnd) to avoid black screenshots.
  • Iconless elements can fall back to a vision LLM: memory/vision_api.template.py; the playbook is in memory/vision_sop.md.
  • A repeatedly stressed pitfall: after screenshot analysis you must use physical coordinates (consistent with ljqCtrl).

memory/ui_detect.pydetect() → list[dict]
# each element is a dict
{
  'bbox': [x1, y1, x2, y2],  # physical-pixel box
  'type': 'icon' | 'text',  # YOLO box = icon, OCR box = text
  'label': str | None,  # None when an icon carries no text
  'confidence': float
}
How match mode works

The default mode='match' runs YOLO once for icon boxes, then a single full-image OCR, and uses _iou() (intersection over the OCR box's area) to "stick" text onto the overlapping icon as its label; any OCR box matched by no icon is emitted on its own as a type='text' element. ~1.2s.

match vs crop

mode='crop' instead crops every YOLO box and stitches them vertically into one tall image (_ocr_crops_batch), OCRs once, and maps results back by y-coordinate — more precise but ~2.3s. Use match day-to-day; switch to crop only when dense small icons are misread.

2 Three OCR pitfalls: ocr_utils.py click to expand
conf and "no text"

RapidOCR has two counter-intuitive points, documented in the header of ocr_utils.py: (1) confidence is a string (result[i][2] is str, not float, so _ocr_rapid must cast it via float(r[2])); (2) it returns None, not an empty list, when there is no text, so you must guard with if not result first.

Remote-desktop black screen

After an RDP disconnect, ImageGrab / mss capture a fully black image. The fix is ocr_window(hwnd): it grabs the window bitmap directly through Win32's PrintWindow API, bypassing the screen buffer so it still works under remote desktop.

Three entry points

ocr_image(img) reads one image, ocr_screen(bbox) grabs a screen region then reads, and ocr_window(hwnd) grabs a window then reads; all three return {text, lines, details}, with bbox and conf inside details.

3 Iconless elements: physical coordinates and the VLM fallback click to expand
Elements with label=None

A pure icon (a gear, an arrow) has no text, so detect() gives it label=None. You then cannot locate it by text, so crop that bbox and hand it to a vision LLM for its meaning — the fallback entry is memory/vision_api.template.py: ask_vision(img, prompt), which supports claude / openai / modelscope backends.

Why physical coordinates are mandatory

On high-DPI screens, "logical coordinates" and "physical pixels" are not the same. Screenshot analysis yields physical-pixel boxes, and the next lesson's clicking via ljqCtrl also reckons in physical coordinates (multiplying by dpi_scale internally) — only when both ends agree does "what you see" line up with "what you click". That is why ui_detect.py prints "after screenshot analysis you must use physical coordinates" the moment it loads.

YOLO cross-process cache

Loading YOLO weights is slow, so _yolo() outsources inference to a resident daemon: it pings 127.0.0.1:31876, and if nothing answers it Popens itself with --yolo-daemon, after which each detection reuses the already-loaded model over HTTP; if the daemon is unavailable it falls back to local inference via _yolo_local.

🧩 Analogy
Like giving the agent a pair of eyes plus a pointing finger: it glances at the screen, recognizes "that blue Send button is at the bottom-right", and lands its finger precisely on that pixel. Even if the software offers no API for programs at all, it can still use it.
✅ Key Takeaways
  • Vision pipeline: capture → detect (YOLO+OCR) → locate → act.
  • detect() returns elements with coordinates; iconless elements can fall back to a VLM.
  • Always use physical coordinates; use ocr_window under remote desktop to avoid black screens.
💡 Design Insight
Vision is GA's "universal fallback": when APIs and HTML both fail, as long as the screen shows something, it can operate. This extends the controllable scope from "software with an API" to "any interface a human eye can use" — which is exactly why GA need not preload an adapter for every app. If it can see it, that is enough.
