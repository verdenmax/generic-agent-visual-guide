对话与斜杠命令Chat & Slash Commands

大部分时间你只是用大白话跟 GenericAgent 说要干嘛。少数时候，你需要管理会话或切换运行模式——这就是斜杠命令的用武之地，最常用的是 /new 和 /continue。

🌍 宏观理解

斜杠命令分两类：一类管会话（开新对话、恢复旧对话），任何前端都有；另一类是高级模式开关（自治、目标模式、多 worker 协作等），主要在终端 UI 的命令面板里。

常用会话命令

命令作用
/new开启新对话，清空当前上下文。
/continue列出可恢复的历史会话快照。
/continue [n]恢复第 n 个会话快照。

进阶模式命令（终端面板）

命令作用
/autorun [seed]进入 autonomous_operation 自主模式。
/goal [goal]进入 Goal 目标模式（需 condition 约束）。
/hive [target]进入 Hive 多 worker 协作模式。
/conductor [task]调用 conductor.py 做多 subagent 编排。
/scheduler启停 reflect 定时任务（由 reflect/scheduler.py 驱动）。
/morphling [target]启用 Morphling 蒸馏 / 吞噬外部技能。
/update [note]git pull 更新 GA 仓库并报告影响面。
🔬 源码对应
  • /new 与 /continue 的派发在 frontends/chatapp_common.py（命令清单 USER_COMMANDS、分支 op == "/new" / "/continue"）。
  • 恢复逻辑在 frontends/continue_cmd.py，它从 temp/model_responses 下的日志解析出历次 Prompt/Response 对与 <summary> 摘要，再列出可恢复会话。
  • 进阶命令的清单与提示词构造在 frontends/slash_cmds.py（PALETTE_ENTRIES 表 + prompt_for / build_*_prompt 函数）。

🔬 深入源码

⚙️ continue_cmd.py 的解析流程

frontends/continue_cmd.py 扫描 temp/model_responses/model_responses_*.txt，每个文件即一段会话。它用 _BLOCK_RE 切出 === Prompt === / === Response === 块，_pairs() 把它们配成 (prompt, response) 对，再交给 _parse_native_history() 还原成 user/assistant 消息列表注回历史。

🧪 预览靠什么生成

会话列表里每行的预览，由 _preview_from_file() 给出：它优先取文件尾窗里最后一个 <summary>（_SUMMARY_RE 匹配），没有或不干净时退回最后一条真实用户提问（_last_user()）。所以一段会话“讲的是什么”，主要由模型自己写的 <summary> 决定。

⚠️ 大日志怎么不卡 UI

日志可能有十几 MB。/continue 的搜索框只在每个文件的头窗（_GREP_WIN = 1 MB）里做内容 grep，预览只读头/尾各 _PREVIEW_WIN = 32 KB，并用 ~/.genericagent/continue_rounds_cache.json 缓存轮数——于是再大的历史也能秒开。

🔀 /restore 与 /continue 的区别

/restore（chatapp_common 的 format_restore）只恢复上一次对话上下文；/continue 则列出多段历史会话快照供挑选，/continue n 恢复第 n 个。前者“接着上次”，后者“在历史里翻一个”。

2 进阶命令的本质：把提示词注入对话 点击展开
⚙️ prompt_for 与 build_*_prompt

终端面板里的 PALETTE_ENTRIES（slash_cmds.py）列出 /update、/autorun、/morphling、/goal、/hive、/conductor、/scheduler。除 /scheduler 外，它们都经 prompt_for(cmd, args) 映射到一个 build_*_prompt 函数，返回一段系统风格提示词，当作用户输入注入同一套 Agent 循环——命令本身不含业务逻辑。

🧪 build_autorun_prompt 长什么样

以 /autorun 为例，它注入的提示词只是“让 Agent 先读一个 SOP，再自驱执行”：

frontends/slash_cmds.pybuild_autorun_prompt
请进入「自主探索 / autonomous 模式」：先读 memory/autonomous_operation_sop.md。全程自驱，不可逆 / 高风险动作先 ask_user，结案给一份简明回执（做了什么 / 产物在哪 / 下一步）。

/goal、/hive、/morphling 同理，各自指向 goal_mode_sop.md / goal_hive_sop.md / morphling_sop.md。

🔀 /scheduler 与 /update 的两个例外味道

/scheduler 是唯一不注入提示词的命令：它直接读写 sche_tasks/*.json 与既有 scheduler 守护进程，无需 LLM。/update 仍是提示词注入，但它写的是一段“先预览上游提交、再保留本地改动地 git pull”的精细编排——真正的 git 工作仍由 Agent 在循环里完成。

❓ 为什么这样设计

因为模式即提示词：加一个新模式，往往只是加一个 build_*_prompt 函数与一行 PALETTE_ENTRIES，不必改内核。命令只是“触发器”，行为长在 Agent 读到的提示词里——这与“工具少、靠提示词组织行为”的整体哲学一致。

🧩 生活类比
斜杠命令像聊天框里的快捷指令：平时你正常聊天，偶尔输入一个“/”开头的口令，就能让助手切换状态——/new 像“清桌重开”，/continue 像“接着上次那盘继续下”。
✅ 关键要点
  • 记三个就够用：/new 清空重开、/continue 看历史、/continue n 恢复第 n 个。
  • 进阶命令（/autorun、/goal、/hive…）主要在终端 UI 的命令面板里。
  • 历史会话存在 temp/model_responses 的日志里，可随时恢复。
💡 设计亮点
许多进阶命令并不是“硬编码的功能”，而是把一段精心写好的提示词注入对话（看 slash_cmds.py 里的 build_*_prompt）。命令只是模式的“触发器”，真正的行为仍由 Agent 读提示词后自己执行——所以加一个新模式，往往只是加一个提示词构造函数，而不必改内核。

Most of the time you just talk to GenericAgent in plain language. Occasionally you need to manage a session or switch run modes — that is where slash commands come in, the most common being /new and /continue.

🌍 The Big Picture

Slash commands come in two kinds: ones that manage the session (start fresh, restore an old conversation), available in every frontend; and advanced mode switches (autonomous, goal mode, multi-worker collaboration), mainly in the terminal UI command palette.

Everyday session commands

CommandWhat it does
/newStart a fresh conversation and clear the current context.
/continueList recoverable conversation snapshots.
/continue [n]Restore the n-th conversation snapshot.

Advanced mode commands (terminal palette)

CommandWhat it does
/autorun [seed]Enter the autonomous_operation self-run mode.
/goal [goal]Enter Goal mode (requires a condition constraint).
/hive [target]Enter Hive multi-worker collaboration mode.
/conductor [task]Invoke conductor.py for multi-subagent orchestration.
/schedulerStart/stop reflect scheduled tasks (driven by reflect/scheduler.py).
/morphling [target]Enable Morphling to distill / absorb external skills.
/update [note]git pull to update the GA repo and report the impact.
🔬 In the Source
  • /new and /continue are dispatched in frontends/chatapp_common.py (the USER_COMMANDS list and the op == "/new" / "/continue" branches).
  • Restore logic lives in frontends/continue_cmd.py, which parses past Prompt/Response pairs and <summary> snippets from the logs under temp/model_responses and lists recoverable sessions.
  • The advanced commands and their prompt builders are in frontends/slash_cmds.py (the PALETTE_ENTRIES table + the prompt_for / build_*_prompt functions).

🔬 Deep Dive

1 How /continue restore works under the hood click to expand
The parse pipeline in continue_cmd.py

frontends/continue_cmd.py scans temp/model_responses/model_responses_*.txt — one file per session. It splits === Prompt === / === Response === blocks with _BLOCK_RE, pairs them via _pairs(), then _parse_native_history() rebuilds a user/assistant message list to inject back into history.

How the preview is built

Each row's preview comes from _preview_from_file(): it prefers the last <summary> in the file's tail window (matched by _SUMMARY_RE), falling back to the last real user prompt (_last_user()) when absent or dirty. So what a session "is about" is mostly decided by the <summary> the model wrote itself.

How huge logs avoid stalling the UI

Logs can be tens of MB. The /continue search box greps only the head window (_GREP_WIN = 1 MB) of each file, the preview reads just _PREVIEW_WIN = 32 KB at head/tail, and round counts are cached in ~/.genericagent/continue_rounds_cache.json — so even a huge history opens instantly.

/restore vs /continue

/restore (format_restore in chatapp_common) only restores the previous conversation context; /continue lists multiple session snapshots to choose from, and /continue n restores the n-th. The former is "resume last", the latter is "pick one out of history".

2 What advanced commands really are: injecting a prompt click to expand
prompt_for and build_*_prompt

The terminal palette's PALETTE_ENTRIES (slash_cmds.py) lists /update, /autorun, /morphling, /goal, /hive, /conductor, /scheduler. Except /scheduler, each is mapped by prompt_for(cmd, args) to a build_*_prompt function that returns a system-style prompt, injected as user input into the same agent loop — the command itself holds no business logic.

What build_autorun_prompt looks like

Take /autorun: the prompt it injects just tells the agent to read an SOP first, then self-run:

frontends/slash_cmds.pybuild_autorun_prompt
Enter "autonomous mode": first read memory/autonomous_operation_sop.md. Self-drive throughout; for irreversible / high-risk actions call ask_user first; on finishing, give a concise receipt (what was done / where artifacts are / next step).

/goal, /hive, /morphling are analogous, each pointing to goal_mode_sop.md / goal_hive_sop.md / morphling_sop.md.

How /scheduler and /update differ

/scheduler is the only command that injects no prompt: it reads/writes sche_tasks/*.json and the existing scheduler daemon directly, no LLM. /update is still a prompt injection, but one that orchestrates "preview upstream commits, then git pull while preserving local changes" — the actual git work still happens in the agent loop.

Why design it this way

Because a mode is a prompt: adding a new mode is often just adding a build_*_prompt function plus one PALETTE_ENTRIES row, with no core change. The command is only a "trigger"; behavior lives in the prompt the agent reads — consistent with the overall philosophy of "few tools, behavior organized by prompts".

🧩 Analogy
Slash commands are like shortcuts in a chat box: you chat normally, and now and then type a "/"-prefixed keyword to flip the assistant's state — /new is "clear the table and start over", /continue is "pick up the previous game where we left off".
✅ Key Takeaways
  • Three are enough for daily use: /new to reset, /continue to list history, /continue n to restore the n-th.
  • Advanced commands (/autorun, /goal, /hive …) live mainly in the terminal UI palette.
  • Past sessions are stored as logs under temp/model_responses and can be restored anytime.
💡 Design Insight
Many advanced commands are not "hard-coded features" but inject a carefully written prompt into the conversation (see the build_*_prompt functions in slash_cmds.py). The command is just a "trigger" for a mode; the real behavior is still carried out by the agent after it reads the prompt — so adding a new mode is often just adding a prompt builder, with no change to the core.
