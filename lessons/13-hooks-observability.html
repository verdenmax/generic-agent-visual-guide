钩子与可观测性Hooks & Observability

想知道每一轮花了多少 token、想给某个工具加一道审计、想接入追踪系统——又不想去改那 100 行核心循环？GenericAgent 用一套钩子（hooks）解决：循环在每个关键时刻“喊一嗓子”，插件们各自接住。

🌍 宏观理解

钩子是一种发布 / 订阅机制：核心循环在固定的时间点触发事件（agent / turn / llm / tool 的 before / after），任何插件都能注册回调来“收听”。核心代码完全不知道有谁在听——这就是“零耦合扩展”。

plugins/hooks.pyregister / trigger
# 插件侧：注册一个回调
@hooks.register('llm_after')
def on_llm_after(ctx):
    ...  # 读 ctx，可返回修改后的 ctx

# 核心侧：循环在关键点触发事件
trigger('llm_after', ctx)  # 在 agent_loop.py 里写作 _hook(...)
🔬 源码对应
  • 机制在 plugins/hooks.py：register(event) 装饰器登记回调，trigger(event, ctx) 依次调用；
  • 循环里成对触发这些事件：agent_before/after · turn_before/after · llm_before/after · tool_before/after（见 agent_loop.py 里的 _hook 调用与 dispatch）。
  • 插件自动发现：discover_and_load 扫描 plugins/ 目录加载模块；plugins/langfuse_tracing.py 就是个现成例子——它注册到上述事件，做调用追踪与 token 用量统计。

🔬 深入源码

1 register / trigger：发布-订阅的全部实现 点击展开
🧪 注册表 + 装饰器 + 触发
plugins/hooks.pyregister / trigger
_registry = {}  # event_name -> [callback, ...]

def register(event):
    def decorator(fn):
        _registry.setdefault(event, []).append(fn); return fn
    return decorator

def trigger(event, ctx: dict):
    for fn in _registry.get(event, []):
        try:
            r = fn(ctx)
            if isinstance(r, dict): ctx = r  # 回调可返回修改后的 ctx
        except Exception as e:
            sys.stderr.write(f'[hooks] {event} callback error: {e}\n')
    return ctx
❓ 回调返回 dict 意味着什么

trigger 不只是“通知”，它还能改写上下文：若某回调返回一个 dict，该 dict 就成为后续回调（以及触发点）看到的新 ctx。这让钩子既能做只读的观测（追踪、计时），也能做轻度干预（改 messages、注入提示）。回调里抛异常会被 try 兜住并打到 stderr，绝不波及主循环。

⚙️ 零侵入的可观测性

langfuse_tracing.py 在 import 时若发现 mykey 里有 langfuse_config 就自激活，并用 @hooks.register 挂到 agent/llm/tool 三对事件上，把每次任务/模型调用/工具执行变成一条 trace span。核心循环对此一无所知——删掉这个插件，agent 照常运行。这就是钩子机制“对扩展开放、对核心封闭”的兑现。

🧩 生活类比
像生产线上的质检探头：流水线该怎么走还怎么走，你只是在“上料前 / 下料后”这些节点装上探头，需要时取数、记录、甚至微调一下零件。要不要装、装几个，都不影响流水线本身的运转。
✅ 关键要点
  • 钩子 = 发布/订阅；核心循环触发事件，插件注册回调收听。
  • 八个事件：agent / turn / llm / tool 的 before / after。
  • plugins/ 目录自动加载；langfuse_tracing.py 是现成的追踪插件。
💡 设计亮点
钩子回调可以返回一个修改后的 ctx——所以它不只是“旁观”，还能“改写”流经的上下文。这让可观测性与轻量扩展用同一套机制实现：既能默默记账，也能在不动核心的前提下调整行为。核心循环始终只有 100 行，能力却能从外面一层层叠加上去。

Want to know how many tokens each turn cost, add an audit to a tool, or wire in a tracing system — without touching the 100-line core loop? GenericAgent solves it with hooks: the loop "calls out" at every key moment, and plugins catch the calls.

🌍 The Big Picture

Hooks are a publish/subscribe mechanism: the core loop fires events at fixed points (the before/after of agent / turn / llm / tool), and any plugin can register a callback to "listen". The core has no idea who is listening — that is "zero-coupling extension".

plugins/hooks.pyregister / trigger
# plugin side: register a callback
@hooks.register('llm_after')
def on_llm_after(ctx):
    ...  # read ctx, may return a modified ctx

# core side: the loop fires events at key points
trigger('llm_after', ctx)  # written as _hook(...) inside agent_loop.py
🔬 In the Source
  • The mechanism is in plugins/hooks.py: the register(event) decorator registers a callback, trigger(event, ctx) calls them in turn;
  • The loop fires these events in pairs: agent_before/after · turn_before/after · llm_before/after · tool_before/after (see the _hook calls in agent_loop.py and dispatch).
  • Plugins are auto-discovered: discover_and_load scans the plugins/ directory and loads modules; plugins/langfuse_tracing.py is a ready example — it registers on those events to do call tracing and token-usage accounting.

What returning a dict means

trigger is not just "notify" — it can rewrite context: if a callback returns a dict, that dict becomes the new ctx seen by later callbacks (and the trigger site). This lets hooks do read-only observation (tracing, timing) or light intervention (edit messages, inject prompts). An exception in a callback is caught by the try and printed to stderr, never disturbing the main loop.

Zero-intrusion observability

langfuse_tracing.py self-activates on import if mykey has a langfuse_config, hanging onto the agent/llm/tool event pairs via @hooks.register to turn each task/model-call/tool-run into a trace span. The core loop knows nothing about it — delete the plugin and the agent runs just the same. That is the hook mechanism delivering "open to extension, closed at the core".

🧩 Analogy
Like inspection probes on an assembly line: the line runs exactly as before; you merely clamp probes onto nodes like "before loading / after unloading" to read data, log, or even tweak a part when needed. Whether you add probes, and how many, does not affect how the line itself runs.
✅ Key Takeaways
  • Hooks = pub/sub; the core loop fires events, plugins register callbacks to listen.
  • Eight events: the before / after of agent / turn / llm / tool.
  • The plugins/ directory is auto-loaded; langfuse_tracing.py is a ready-made tracing plugin.
💡 Design Insight
A hook callback can return a modified ctx — so it does more than "observe"; it can "rewrite" the context flowing through. This lets observability and lightweight extension share one mechanism: quietly keep accounts, or adjust behavior without touching the core. The core loop stays 100 lines, yet capabilities can be layered on from the outside.
