常见疑问 / FAQ

1 为什么核心只有 ~3K 行也能这么强？ 点击展开
一句话

复杂度被外包了：推理交给大模型，扩展交给 code_run（运行时写代码），经验交给分层记忆。框架只提供“循环 + 9 工具 + 记忆”的最小骨架。详见 第 1 课 与 第 20 课。

2 它支持哪些大模型？ 点击展开
两种协议

GA 原生支持 OpenAI 兼容接口与 Anthropic Claude 原生接口，因此 GPT / Claude / Kimi / MiniMax / DeepSeek / GLM / Qwen / Gemini 等都能在 mykey.py 里配置。连不支持函数调用的模型，也能用文本协议调工具（见 第 9 课）。

3 记忆会不会越记越乱？ 点击展开
靠铁律守住

不会。L0 铁律规定“无行动，不记忆”——只有经工具调用验证成功的结论才允许写入；并禁止存易变状态、要求最小化 patch。所以记忆库是“越用越准”而非“越用越脏”。详见 第 12 课。

FAQ

1 How can a ~3K-line core be this capable? click to expand
In one line

Complexity is outsourced: reasoning to the LLM, extension to code_run (writing code at runtime), experience to layered memory. The framework only provides a minimal "loop + 9 tools + memory" skeleton. See lesson 01 and lesson 20。

2 Which LLMs does it support? click to expand
Two protocols

GA natively speaks the OpenAI-compatible and Anthropic Claude native protocols, so GPT / Claude / Kimi / MiniMax / DeepSeek / GLM / Qwen / Gemini and more can be configured in mykey.py. Even models without function calling can use tools via the text protocol (see lesson 09）。

3 Won't memory get messier over time? click to expand
Guarded by iron rules

No. The L0 rules state "no execution, no memory" — only conclusions verified by a successful tool call may be written; volatile state is banned and patches must be minimal. So the store gets "more accurate", not "dirtier". See lesson 12。
