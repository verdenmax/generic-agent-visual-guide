自进化机制详解The Self-Evolution Mechanism

这是 GenericAgent 与其他框架本质上的不同：它不靠预装技能取胜，而是每解决一个新任务，就把这次的成功路径结晶成一个可复用的 Skill。用得越久，技能越多——长成一棵只属于你的技能树。

🌍 宏观理解

自进化是一个闭环：新任务 → 自主探索（装依赖、写脚本、调试、验证）→ 把成功路径结晶进记忆 → 下次遇到相似任务直接召回。第一次可能要折腾很久，但只要成功，这份经验就永久留下，从此一句话搞定。

自进化闭环

1

新任务

来了一件它还不会的事。

2

自主探索

用 code_run 装依赖、写脚本、调试，直到行动验证成功。

3

结晶为 Skill

start_long_term_update 把要点写进 L3 SOP，并在 L1 索引登记。

4

下次直接召回

相似任务再来，顺着 L1 索引找到 SOP，一步到位。

🔬 源码对应
  • 结晶靠第 12 课的 start_long_term_update；技能存在 L3（memory/ 下的 *_sop.md），由 L1 索引导航。
  • 技能检索见 memory/skill_search/（含 SKILL.md 与检索能力），帮 Agent 在技能库里找到该用哪条 SOP。
  • 两种进阶进化：memory/morphling_sop.md（Morphling：抽取目标项目的目标+测例，吸收/复刻其能力）与 memory/incubator_sop.md（Incubator：把自己复制部署到其他节点，各自带独立记忆）。

步骤做什么用到的零件
① 新任务来了件它还不会的事put_task(...)
② 自主探索装依赖 / 写脚本 / 调试 / 验证code_run, file_write
③ 结晶把成功要点写进 L3 SOP，登记 L1 索引start_long_term_update
④ 召回相似任务顺着 L1 找到 SOPmemory/skill_search/
⚙️ “结晶”内部怎么走

结晶不是“把整段对话存下来”，而是提炼：用 start_long_term_update 只写下复用必需的要点——脚本路径、关键命令、踩过的坑——成为 memory/ 下的一个 *_sop.md（L3），并在 L1 全局索引里登记一行指针。下次靠这行指针就能找回整条 SOP。

⚠️ 无行动，不记忆

步骤③只在步骤②真正跑通并验证成功后才触发。没被行动验证过的“想法”不许结晶——否则记忆里会沉淀一堆没跑通的假经验，越用越坏。这是 L0 记忆铁律（见 memory/memory_management_sop.md）。

2 skill_search：在 10 万+ 技能卡里找“该用哪条 SOP” 点击展开
🧪 最简调用
memory/skill_search/SKILL.mdsearch()
import sys; sys.path.append('../memory/skill_search')
from skill_search import search

results = search("python send email")  # 必须用英文查询
for r in results:
    s = r.skill
    print(f"[{r.final_score:.2f}] {s.name} — {s.one_line_summary}")
❓ 为什么必须用英文查询

据 SKILL.md 的明确提示：中文匹配效果极差，所以查询要用英文（如 "docker deployment"）。技能库是语义检索，英文 query 命中的相关度和质量分都更高。

⚙️ 返回里有什么、内部怎么走

search(query, env=None, category=None, top_k=10) 返回一组 SearchResult（见 skill_search/engine.py），每条带 final_score / relevance / quality 与一个 SkillIndex（含 key、one_line_summary、category、form、autonomous_safe）。它是个零依赖 API 客户端，默认打到内置地址 http://www.fudankw.cn:58787，可用环境变量 SKILL_SEARCH_API 覆盖。

🔀 和“把所有技能塞进上下文”对比

若把上万条技能全列进 prompt，上下文会爆炸、模型会分心。skill_search 反过来——按需检索，只把最相关的几条召回，既省 token 又少噪声，正是“做减法”哲学在记忆侧的体现。

3 两种进阶进化：Morphling（吸收）与 Incubator（复制） 点击展开
🧪 Morphling 的核心三元组

据 memory/morphling_sop.md，Morphling 是项目级能力吸收/替代：给定任意目标项目，围绕三元组工作——目标（Target，它解决什么）、测例（Tests，怎么验证）、行为（Actions，逐组件决定调用 / 重写 / 舍弃）。最终让自身或新产物在同一测例上达到或超过目标。

⚙️ Morphling 怎么执行

“更好”不能靠主观判断，必须落在可测维度（通过率 / 性能 / 成本 / 稳定性 / 易用性）。SOP 还规定它应通过 Goal Hive 执行（见 goal_hive_sop）：Master 调度 + Worker 并行实现 + 持续验收的长程模式。

🧪 Incubator：自我复制到其他节点

据 memory/incubator_sop.md，Incubator 把 GA 复制部署到任意节点，组成一张 agent 网络，每个节点有独立记忆，可通过编辑其 memory/ 来干预行为。通信走与 subagent 相同的协议：agentmain.py --task {name} --input "..."。

⚠️ Incubator 的关键坑点

SOP 明确警告：不要复制 L1/L2 文件（global_mem(_insight).txt），它们会在新节点自动初始化；也不要复制 memory/ 下未被 gitignore 白名单的文件。否则新节点会带着别人的“私货记忆”出生，污染它本应独立生长的技能树。

🧩 生活类比
像一个会写菜谱的厨师：第一次做一道新菜，要查资料、试比例、可能翻几次车；一旦做成，他就把“火候、用量、步骤”写成一张菜谱收进菜谱本。下次再点这道菜，照谱做，又快又稳。日子久了，他的菜谱本独一无二——别的厨师没有。
✅ 关键要点

  • 技能存 L3 SOP、由 L1 索引导航、用 skill_search 检索。
  • 进阶：Morphling 吸收外部项目能力，Incubator 自我复制部署。
💡 设计亮点
自进化把“能力”从出厂预置变成了运行时生长。这也解释了前面所有设计为何如此克制：极简的循环、九个原子工具、严格“行动验证”的记忆——都是为了让“探索 → 结晶 → 召回”这个飞轮转得稳、转得久。于是 3K 行种子代码不是终点，而是起点：真正的能力，是你和它一起长出来的。

This is what makes GenericAgent fundamentally different: it does not win by preloading skills, but by crystallizing each successful path into a reusable Skill whenever it solves a new task. The longer you use it, the more skills accumulate — growing a skill tree that is uniquely yours.

🌍 The Big Picture

Self-evolution is a closed loop: new task → autonomous exploration (install deps, write scripts, debug, verify) → crystallize the successful path into memory → directly recall it next time a similar task appears. The first time may take a lot of fiddling, but once it succeeds, that experience stays forever, and from then on one sentence does it.

The self-evolution loop

1

New task

Something it cannot yet do arrives.

2

Autonomous exploration

Use code_run to install deps, write scripts, debug, until action-verified success.

3

Crystallize into a Skill

start_long_term_update writes the essentials into an L3 SOP and registers it in the L1 index.

4

Direct recall next time

When a similar task returns, follow the L1 index to the SOP and do it in one shot.

🔬 In the Source
  • Crystallization uses lesson 12's start_long_term_update; skills live in L3 (the *_sop.md files under memory/), navigated by the L1 index.
  • Skill retrieval is in memory/skill_search/ (with SKILL.md and a search capability), helping the agent find which SOP to use.
  • Two advanced evolutions: memory/morphling_sop.md (Morphling: extract a target project's goals + tests and absorb/replicate its abilities) and memory/incubator_sop.md (Incubator: replicate and deploy itself to other nodes, each with independent memory).

What "crystallize" does internally

Crystallizing is not "save the whole transcript" — it is distillation: start_long_term_update records only what reuse needs — the script path, key commands, the pitfalls hit — as one *_sop.md (L3) under memory/, and registers a one-line pointer in the L1 global index. Next time that pointer leads straight back to the whole SOP.

No action, no memory

Step ③ fires only after step ② actually runs and verifies success. An "idea" never proven by action may not crystallize — otherwise memory fills with un-run, false experience that rots with use. This is the L0 memory rule (see memory/memory_management_sop.md).

2 skill_search: finding "which SOP to use" among 100K+ skill cards click to expand
The minimal call
memory/skill_search/SKILL.mdsearch()
import sys; sys.path.append('../memory/skill_search')
from skill_search import search

results = search("python send email")  # queries must be in English
for r in results:
    s = r.skill
    print(f"[{r.final_score:.2f}] {s.name} — {s.one_line_summary}")
Why queries must be English

Per SKILL.md's explicit note: Chinese matches poorly, so queries should be English (e.g. "docker deployment"). The library is semantic search, and English queries score higher on relevance and quality.

What it returns and how it works

search(query, env=None, category=None, top_k=10) returns a list of SearchResult (see skill_search/engine.py), each carrying final_score / relevance / quality and a SkillIndex (with key, one_line_summary, category, form, autonomous_safe). It is a zero-dependency API client hitting a built-in default http://www.fudankw.cn:58787, overridable via SKILL_SEARCH_API.

vs stuffing every skill into context

Listing tens of thousands of skills in the prompt would explode context and distract the model. skill_search inverts this — retrieve on demand, recalling only the few most relevant — saving tokens and noise, the "subtract" philosophy applied to memory.

3 Two advanced evolutions: Morphling (absorb) and Incubator (replicate) click to expand
Morphling's core triple

Per memory/morphling_sop.md, Morphling is project-level capability absorption/replacement: given any target project, work around a triple — Target (what it solves), Tests (how to verify), Actions (per component: call / rewrite / discard) — until oneself or a new product matches or beats the target on the same tests.

How Morphling executes

"Better" cannot be subjective — it must land on a measurable axis (pass rate / speed / cost / stability / usability). The SOP also mandates it run via Goal Hive (see goal_hive_sop): Master scheduling + parallel Workers + continuous acceptance, a long-horizon pattern.

Incubator: self-replicate to other nodes

Per memory/incubator_sop.md, Incubator replicates and deploys GA to any node, forming an agent network where each node has independent memory, steerable by editing its memory/. Communication uses the same protocol as subagents: agentmain.py --task {name} --input "...".

Incubator's key pitfall

The SOP warns explicitly: do not copy L1/L2 files (global_mem(_insight).txt) — they auto-initialize on the new node — nor any file under memory/ outside the gitignore whitelist. Otherwise the new node is born carrying someone else's memory, polluting the skill tree it should grow independently.

🧩 Analogy
Like a chef who writes recipes: the first time he makes a new dish he researches, tries ratios, maybe fails a few times; once it works, he writes the "heat, amounts, steps" into a recipe and files it. Next time the dish is ordered, he cooks from the recipe — fast and reliable. Over time his recipe book is one of a kind — no other chef has it.
✅ Key Takeaways
  • Loop: new task → autonomous exploration → crystallize into a Skill → recall next time.
  • Skills live in L3 SOPs, are navigated by the L1 index, and found via skill_search.
  • Advanced: Morphling absorbs external project abilities; Incubator self-replicates and deploys.
💡 Design Insight
Self-evolution turns "capability" from factory-preset into grown at runtime. This explains why every earlier design is so restrained: the minimal loop, the nine atomic tools, the strict "action-verified" memory — all to keep the "explore → crystallize → recall" flywheel spinning steadily and long. So 3K lines of seed code is not the destination but the starting point: the real capability is what you and it grow together.
