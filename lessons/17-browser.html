浏览器注入与 Web 工具Browser Injection & Web Tools

GenericAgent 操作网页有个杀手锏：它注入你真实的浏览器，而不是另起一个干净的无头浏览器。这意味着你的登录态、Cookie、插件全都在——它看到的就是你看到的那个已登录页面。

🌍 宏观理解

网页能力只有两个工具：web_scan（看：拿到一份简化后的页面与标签页列表）和 web_execute_js（做：在页面里执行 JS）。背后由一个 WebSocket 桥把命令送进真实浏览器，页面则先被大幅简化再交给模型，省 token。

ga.pyweb tools → simphtml
import simphtml
from TMWebDriver import TMWebDriver
driver = TMWebDriver()  # 连真实浏览器的 WS 桥

# web_scan 看页面
content = simphtml.get_html(driver, cutlist=True, maxchars=35000)

# web_execute_js 操作页面
result = simphtml.execute_js_rich(script, driver)
🔬 源码对应
  • 注入桥是 TMWebDriver.py：它跑一个 WebSocket 服务，浏览器侧的客户端连回来，从而在真实浏览器里执行 JS、保留登录态。
  • 页面简化是 simphtml.py：get_html 把 DOM 压到约 35000 字、去掉隐藏/浮动/被遮挡元素；execute_js_rich 执行 JS 并回收结果。
  • 两个工具的封装在 ga.py: do_web_scan / do_web_execute_js；上手与配置见 memory/tmwebdriver_sop.md 与 memory/web_setup_sop.md。

🔬 深入源码

1 TMWebDriver：浏览器“连回来”的 WS 桥 点击展开
⚙️ 内部怎么走

TMWebDriver() 在本机起一个 WebSocket 服务（默认 127.0.0.1:18765）外加一个 HTTP 长轮询服务。你浏览器里的用户脚本/扩展作为客户端主动连回来注册成一个 Session（每个标签页一个），之后 execute_js(code) 把脚本下发到对应标签页执行并回收结果。

❓ 为什么是“浏览器连回来”

反过来——由代码启动一个无头浏览器——就丢了你的登录态、Cookie 和插件。让你已经登录的真实浏览器主动连上桥，代码就在那个上下文里执行 JS，于是“它看到的页面 = 你看到的页面”，免登录、免验证码。

🔀 多协议与远程

Session 支持 ws / ext_ws / http 三类客户端，http 走 5 秒长轮询兜底；构造时还会探测 port+1 判断是否 is_remote，是则把命令转发到远端的 /link，从而支持“控制另一台机器的浏览器”。

⚙️ cutlist 砍掉重复列表

cutlist=True 时，先用 findMainList 找出页面里的重复列表（如 50 条商品），对每个长列表只保留前 3 条（或命中 instruction 的 6 条），其余 decompose() 删掉并插一条 [FAKE ELEMENT] N more items hidden 提示。50 条变 3 条，token 立省一大截。

⚠️ 还会丢掉什么

在 optimize_html_for_tokens 阶段，隐藏 / 浮动 / 被遮挡的元素会被剔除——它们对模型理解“主体内容”没用却很占字。最后若仍超 maxchars，用 smart_truncate 按预算就地裁剪。所以 web_scan 看到的是主体的精简版，边栏/广告/隐藏层往往不在里面。

3 execute_js_rich 与 ga.py 接线 点击展开
🧪 富返回值

execute_js_rich(script, driver) 不只回 JS 的返回值，还顺带告诉模型“页面发生了什么”：js_return（脚本结果）、newTabs（执行期间新开的标签页）、transients（一闪而过的提示）、diff（DOM 变化量与最显著变化）。

⚙️ 变化监控怎么做

执行前先抓一份 baseline HTML（注入 temp_monitor_js），执行后再抓一份，用 find_changed_elements 对比得出 DOM 变化量；若 0 变化且无瞬时提示无新标签，就回 “页面无明显变化”，提醒模型这步可能没生效。

🔀 两个工具如何接线

在 ga.py 里，web_scan → simphtml.get_html(driver, cutlist=True, maxchars=35000)，web_execute_js → simphtml.execute_js_rich(script, driver)，外面再包成工具方法 do_web_scan / do_web_execute_js。官方建议多用 execute_js，少全量 scan——scan 贵，定点 JS 既准又省。

🧩 生活类比
别的框架像派来一个陌生的隐身访客：每次都开一个全新、没登录的浏览器，进站还得重新登录、过验证。GA 则像在你自己已经登录好的浏览器里多了一只“隔空操作的手”——你已经登进去的网站，它直接就能用。
✅ 关键要点
  • 两个工具：web_scan（看简化页面）与 web_execute_js（执行 JS）。
  • TMWebDriver 用 WebSocket 注入真实浏览器，保留登录态。
  • simphtml 把页面压到约 35K 字，省 token；多用 execute_js，少全量 scan。
💡 设计亮点
“注入真实浏览器”这一个选择，绕开了无数自动化的老大难：免登录、免验证码、和你看到的页面完全一致。再叠加 simphtml 的页面简化，把动辄上百 KB 的 DOM 压成几十 KB——既看得见，又看得起。这正是第 14 课“token 效率”在网页场景的延伸：用真实环境换可靠，用简化换便宜。

GenericAgent has a killer feature for the web: it injects into your real browser rather than spinning up a clean headless one. That means your login state, cookies and extensions are all there — it sees the very logged-in page you see.

🌍 The Big Picture

There are only two web tools: web_scan (look: get a simplified page plus the tab list) and web_execute_js (do: run JS in the page). Behind them a WebSocket bridge delivers commands into the real browser, and the page is heavily simplified before reaching the model to save tokens.

ga.pyweb tools → simphtml
import simphtml
from TMWebDriver import TMWebDriver
driver = TMWebDriver()  # WS bridge to the real browser

# web_scan look at the page
content = simphtml.get_html(driver, cutlist=True, maxchars=35000)

# web_execute_js act on the page
result = simphtml.execute_js_rich(script, driver)
🔬 In the Source
  • The injection bridge is TMWebDriver.py: it runs a WebSocket server that a browser-side client connects back to, executing JS in the real browser and preserving the login session.
  • Page simplification is simphtml.py: get_html shrinks the DOM to ~35000 chars and drops hidden/floating/covered elements; execute_js_rich runs JS and collects the result.
  • The two tools are wrapped in ga.py: do_web_scan / do_web_execute_js; setup and usage in memory/tmwebdriver_sop.md and memory/web_setup_sop.md.

🔬 Deep Dive

1 TMWebDriver: the WS bridge the browser "connects back" to click to expand
How it works inside

TMWebDriver() starts a local WebSocket server (default 127.0.0.1:18765) plus an HTTP long-poll server. A userscript/extension inside your browser is the client that connects back and registers as a Session (one per tab); thereafter execute_js(code) ships the script to that tab, runs it, and collects the result.

Why "the browser connects back"

The opposite — having code launch a headless browser — loses your login state, cookies and extensions. By letting your already-logged-in real browser connect to the bridge, the code runs JS in that very context, so "the page it sees = the page you see" — no re-login, no captchas.

Multi-protocol and remote

A Session supports ws / ext_ws / http clients, with http falling back to a 5-second long poll; the constructor also probes port+1 to decide is_remote, and if so forwards commands to a remote /link — enabling "drive a browser on another machine".

cutlist trims repeated lists

With cutlist=True, it first finds repeated lists on the page via findMainList (e.g. 50 product rows) and for each long list keeps only the first 3 (or 6 that match instruction), decompose()s the rest and inserts a [FAKE ELEMENT] N more items hidden hint. 50 rows become 3 — a big token saving.

What else gets dropped

During optimize_html_for_tokens, hidden / floating / covered elements are stripped — useless for understanding the "main content" yet costly in characters. If it still exceeds maxchars, smart_truncate trims in place to budget. So web_scan shows a condensed version of the main body; sidebars/ads/hidden layers are often absent.

3 execute_js_rich and the ga.py wiring click to expand
A rich return value

execute_js_rich(script, driver) returns not just the JS result but also tells the model "what happened to the page": js_return (the script result), newTabs (tabs opened during execution), transients (flash-by toasts), and diff (how much the DOM changed and the most significant change).

How change monitoring works

It grabs a baseline HTML first (injecting temp_monitor_js), grabs another after execution, and diffs them via find_changed_elements to report a DOM change count; if there were zero changes, no transient toasts and no new tabs, it returns "no visible change", warning the model this step may not have taken effect.

How the two tools are wired

In ga.py, web_scan → simphtml.get_html(driver, cutlist=True, maxchars=35000), and web_execute_js → simphtml.execute_js_rich(script, driver), wrapped as the tool methods do_web_scan / do_web_execute_js. The guidance is to prefer execute_js and scan sparingly — scan is expensive, targeted JS is both precise and cheap.

🧩 Analogy
Other frameworks are like sending a stranger in incognito: every time a brand-new, logged-out browser opens and must re-login and pass checks. GA is more like an extra "remote hand" inside your own already-logged-in browser — the sites you are already signed into, it can use right away.
✅ Key Takeaways
  • Two tools: web_scan (read a simplified page) and web_execute_js (run JS).
  • TMWebDriver injects the real browser over WebSocket, preserving the login session.
  • simphtml shrinks the page to ~35K chars to save tokens; prefer execute_js, scan sparingly.
💡 Design Insight
The single choice to "inject the real browser" sidesteps countless automation headaches: no re-login, no captchas, and a page identical to what you see. Layered with simphtml's page simplification, a DOM of hundreds of KB shrinks to tens of KB — visible and affordable at once. This extends lesson 14's "token efficiency" to the web: trade the real environment for reliability, and simplification for cost.
