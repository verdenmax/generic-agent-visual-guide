安装与启动Install & Launch

GenericAgent 的安装非常轻：装好一个隔离的 Python 环境、填一把模型 API key，就能跑起来。它故意不预装一大堆依赖——需要什么能力，交给 Agent 自己在运行时去长。

🌍 宏观理解

有两条安装路线。普通用户用一行安装脚本，它会自带一个隔离的 Python 和 Git，再下载一个开箱即用的包；装完直接运行桌面端即可。开发者则克隆仓库、用 uv 建虚拟环境、可编辑安装，然后填 key 启动——这条路更适合读源码、改代码。

开发者安装四步

1

克隆仓库

git clone … && cd GenericAgent

2

建环境

uv venv

用 uv 建一个隔离虚拟环境。

3

装依赖

uv pip install -e ".[ui]"

可编辑安装核心 + UI 依赖（pyproject.toml 里的 [ui] 额外组）。

4

填 key 并启动

cp mykey_template.py mykey.py

python launch.pyw

把模型 API key 填进 mykey.py，然后启动。

⚠️ Python 版本

务必使用 Python 3.11 或 3.12。不要用 3.14——它与 pywebview 及若干 GA 依赖不兼容。一行安装脚本自带隔离 Python，通常无需你手动配 Python。

🔬 源码对应
  • 完整安装说明在 docs/installation.md（中文版 docs/installation_zh.md，新手向 docs/GETTING_STARTED.md）。
  • 密钥模板是 mykey_template.py；GA 原生支持两种协议：OpenAI 兼容接口与 Anthropic Claude 原生接口，因此 GPT / Claude / Kimi / MiniMax / DeepSeek / GLM / Qwen / Gemini 等都能配。
  • 依赖在 pyproject.toml 里声明，UI 相关放在 [ui] 额外组；启动入口是 launch.pyw。也可用 python assets/configure_mykey.py 交互式配置密钥。

2 mykey.py 与两种 API 协议：模型怎么配 点击展开
🧪 一个最简配置

把 mykey_template.py 复制成 mykey.py，填一个 provider 即可。OpenAI 兼容的最简例子（变量名含 native+oai → NativeOAISession）：

mykey.pynative_oai_config
native_oai_config = {
    'apikey': 'sk-<your-openai-key>',
    'apibase': 'https://api.openai.com/v1',
    'model': 'gpt-5.4',
}
⚙️ agentmain 如何按变量名路由

据 mykey_template.py 顶部说明：agentmain.py 只扫描变量名同时含 api/config/cookie 的条目，再按名字里的关键字决定实例化哪个 Session 类——

变量名关键字Session 类
native + claudeNativeClaudeSession
native + oaiNativeOAISession
claude（无 native）ClaudeSession
oai（无 native）LLMSession
mixinMixinSession

所以命名即配置：native_claude_xxx 走原生 Claude，native_oai_xxx 走原生 OpenAI。

❓ Native 与非 Native 的区别

Native = 工具调用走 API 文档里的 tool 字段（function calling），这是 Claude Code / Codex 的原生方式；被 API tool 字段“训到 overfit”的模型（如 Claude Opus/Sonnet）只认这种格式。非 Native 把工具描述塞进 text 字段（文本协议），兼容性更强但对这类模型效果打折。mykey_template.py 建议新手优先用 native_claude_config / native_oai_config。

🧪 能配哪些模型

因为 GA 原生说两种协议，凡是提供 OpenAI 兼容或 Anthropic Messages 兼容端点的家族都能配：GPT 家族、Claude、Kimi、MiniMax、DeepSeek、GLM（智谱 /api/anthropic）、Qwen、Gemini（经 OAI 兼容网关）等——mykey_template.py 里对它们各给了注释示例。

3 Python 3.14 / pywebview 坑，以及 [ui] 额外组 点击展开
⚠️ 为什么不能用 3.14

pyproject.toml 把 requires-python 钉在 >=3.10,<3.14。docs/installation.md 明确：3.14 与 pywebview 及若干 GA 依赖不兼容；若系统 python 是 3.14，改用一行安装脚本，或用 uv 建一个 3.11 / 3.12 环境。

🧪 [ui] 额外组里有什么

pyproject.toml 的 [project.optional-dependencies] 把 UI 依赖单独归到 ui 组——核心很瘦，UI 是按需加装的：

pyproject.toml[ui]
ui = [
    "streamlit>=1.28",
    "pywebview>=4.0",
    "textual>=0.70",
    "prompt_toolkit>=3.0,<4",
    "rich>=13.0",
    "pillow>=9.0",
]

所以 .[ui] 才装上 Streamlit / pywebview / Textual。IM 机器人依赖另在 all-frontends 组，需要哪台机器人才装。

⚙️ configure_mykey.py 是什么

不想手改字典，可运行 python assets/configure_mykey.py 交互式填写密钥（docs/installation.md「Configure your LLM key」一节列为可选 helper）。它只是 mykey.py 的一个引导器，最终落地的仍是那张 *_config 字典。

🧩 生活类比
像租一间毛坯但通水电的厨房：你先接上水电（Python 环境）、挂上门牌（API key），就能开火。至于打蛋器、烤箱这些专用工具，等真要做某道菜时，厨师（Agent）自己去买、去装——而不是开业前先把一整面墙堆满你可能永远用不到的器材。
✅ 关键要点
  • 两条路：用户走一行安装脚本 + 桌面端；开发者走 uv + 可编辑安装。
  • Python 用 3.11 / 3.12，避开 3.14。
  • 核心配置只有一处：mykey.py 里的模型 API key。
  • 启动用 python launch.pyw。
💡 设计亮点
“装得少”本身就是设计的一部分。GenericAgent 不在安装时穷举所有依赖，而是让 Agent 在执行任务时按需自己安装（通过 code_run）。安装步骤越短，意味着能力不是被“配置”出来的，而是被“长”出来的——这正呼应了它“不预设技能、靠进化获得能力”的核心哲学。

Installing GenericAgent is light: set up an isolated Python environment, fill in one model API key, and you are running. It deliberately avoids preloading a pile of dependencies — whatever capability you need, the agent grows it at runtime.

🌍 The Big Picture

There are two install paths. Regular users run a one-line installer that ships an isolated Python and Git and downloads a ready-to-run package; then just launch the desktop app. Developers clone the repo, create a virtualenv with uv, do an editable install, fill in the key and launch — this path is better for reading and changing the source.

Developer install in four steps

1

Clone the repo

git clone … && cd GenericAgent

2

Create the env

uv venv

Create an isolated virtualenv with uv.

3

Install deps

uv pip install -e ".[ui]"

Editable install of core + UI deps (the [ui] extra in pyproject.toml).

4

Add your key & launch

cp mykey_template.py mykey.py

python launch.pyw

Put your model API key into mykey.py, then launch.

⚠️ Python version

Use Python 3.11 or 3.12. Do not use 3.14 — it is incompatible with pywebview and a few GA dependencies. The one-line installer ships an isolated Python, so manual Python setup is usually unnecessary.

🔬 In the Source
  • Full install docs live in docs/installation.md (Chinese: docs/installation_zh.md, getting-started: docs/GETTING_STARTED.md).
  • The key template is mykey_template.py; GA natively speaks two protocols: OpenAI-compatible and Anthropic Claude native, so GPT / Claude / Kimi / MiniMax / DeepSeek / GLM / Qwen / Gemini and others can all be configured.
  • Dependencies are declared in pyproject.toml, with UI extras grouped under [ui]; the launch entry is launch.pyw. You can also run python assets/configure_mykey.py to configure the key interactively.

2 mykey.py and the two API protocols: how models are configured click to expand
A minimal config

Copy mykey_template.py to mykey.py and fill one provider. A minimal OpenAI-compatible example (a var name with native+oai → NativeOAISession):

mykey.pynative_oai_config
native_oai_config = {
    'apikey': 'sk-<your-openai-key>',
    'apibase': 'https://api.openai.com/v1',
    'model': 'gpt-5.4',
}
How agentmain routes by variable name

Per the header of mykey_template.py: agentmain.py only scans entries whose variable name contains api/config/cookie, then picks a Session class by the keywords in that name —

Name keywordSession class
native + claudeNativeClaudeSession
native + oaiNativeOAISession
claude (no native)ClaudeSession
oai (no native)LLMSession
mixinMixinSession

So the name is the config: native_claude_xxx goes native Claude, native_oai_xxx goes native OpenAI.

Native vs non-Native

Native = tool calls use the API's native tool field (function calling), the way Claude Code / Codex work; models overfit to that field (e.g. Claude Opus/Sonnet) only recognize this format. Non-Native stuffs tool descriptions into the text field (a text protocol) — more compatible but weaker for such models. mykey_template.py recommends beginners prefer native_claude_config / native_oai_config.

Which models can be configured

Because GA natively speaks two protocols, any family exposing an OpenAI-compatible or Anthropic-Messages-compatible endpoint works: GPT family, Claude, Kimi, MiniMax, DeepSeek, GLM (Zhipu /api/anthropic), Qwen, Gemini (via an OAI-compatible gateway) and more — mykey_template.py ships a commented example for each.

3 The Python 3.14 / pywebview pitfall, and the [ui] extra click to expand
Why not 3.14

pyproject.toml pins requires-python to >=3.10,<3.14. docs/installation.md states plainly: 3.14 is incompatible with pywebview and a few GA deps; if your system python is 3.14, use the one-line installer or create a 3.11 / 3.12 env with uv.

What is inside the [ui] extra

In pyproject.toml the [project.optional-dependencies] group isolates UI deps under ui — the core stays lean, UI is opt-in:

pyproject.toml[ui]
ui = [
    "streamlit>=1.28",
    "pywebview>=4.0",
    "textual>=0.70",
    "prompt_toolkit>=3.0,<4",
    "rich>=13.0",
    "pillow>=9.0",
]

So .[ui] is what pulls in Streamlit / pywebview / Textual. IM-bot deps live in a separate all-frontends group, installed only if you need a given bot.

What configure_mykey.py is

If you would rather not hand-edit the dict, run python assets/configure_mykey.py for an interactive key setup (listed as an optional helper under "Configure your LLM key" in docs/installation.md). It is just a wizard for mykey.py; what it produces is still that *_config dict.

🧩 Analogy
It is like renting a bare kitchen with water and power hooked up: connect the utilities (the Python env), hang your nameplate (the API key), and you can start cooking. The specialty tools — the whisk, the oven — are bought and installed by the chef (the agent) only when a dish actually needs them, instead of cramming a whole wall with gear you may never use before opening day.
✅ Key Takeaways
  • Two paths: users take the one-line installer + desktop app; developers take uv + editable install.
  • Use Python 3.11 / 3.12; avoid 3.14.
  • The only core config is your model API key in mykey.py.
  • Launch with python launch.pyw.
💡 Design Insight
Installing little is itself part of the design. GenericAgent does not enumerate every dependency at install time; it lets the agent install what it needs on demand (via code_run) while doing a task. A short install means capability is not "configured" but grown — echoing its core philosophy of not preloading skills but evolving them.
