记忆的读写与结晶Memory & Crystallization

分好层只是“书架”，还得有人往上面记东西。GenericAgent 用两个记忆工具完成读写：一个是任务进行中的“工作便签”，一个是任务收尾时的“长期记忆结算”。前者防遗忘，后者把经验结晶成技能。

🌍 宏观理解

短期：update_working_checkpoint 把“用户要什么、关键约束”写进一个便签，之后每轮自动注入，防止长任务跑着跑着把目标跑丢。长期：start_long_term_update 在任务完成后启动“结算”，把经过行动验证的环境事实/用户偏好/踩坑经验，最小化地写进 L1/L2/L3。

🔬 源码对应
  • 短期便签：ga.py: do_update_working_checkpoint 把 key_info / related_sop 写进 self.working，再由“锚点提示”每轮回灌给模型。
  • 长期结算：ga.py: do_start_long_term_update 注入一段提炼提示词，引导用 file_patch 最小化更新 L2 事实、同步 L1 索引、必要时精简 L3 SOP。
  • 结算受 L0 铁律约束：memory/memory_management_sop.md——只记“行动验证成功”的信息，禁存易变状态，能不改就不 overwrite、宁愿少量 patch。
🧩 生活类比
像做实验时手边的草稿纸 + 事后的实验记录本：草稿纸（工作便签）随手记当前要点，做完一组就擦；只有真正验证成功的结论，才郑重地誊进永久的记录本（长期记忆）。没验证过的猜测，绝不入册。
✅ 关键要点
  • 两个记忆工具：working_checkpoint（短期、每轮注入）与 start_long_term_update（长期结晶）。
  • 铁律：无行动，不记忆——只结晶经过验证的信息。
  • 写记忆要最小化：优先小 patch，禁存易变状态。
💡 设计亮点
“无行动，不记忆”这条铁律，是 GA 记忆可信的关键。模型的“固有知识”“推理猜测”一律不准当事实写入——只有工具调用真正成功的结论才配结晶成技能。正是这条原则，把记忆库守成了“越用越准”而不是“越用越脏”，也让后面“自进化”长出的技能树根基扎实、可被反复信任。

Layering is just the "bookshelf"; something still has to write onto it. GenericAgent reads and writes memory with two memory tools: a "working notepad" during a task, and a "long-term memory settlement" when a task wraps up. The first prevents forgetting; the second crystallizes experience into skills.

🌍 The Big Picture

Short-term: update_working_checkpoint writes "what the user wants and the key constraints" onto a notepad that is auto-injected every turn, so a long task does not lose its goal along the way. Long-term: start_long_term_update kicks off a "settlement" after a task, writing action-verified environment facts, user preferences and hard-won lessons minimally into L1/L2/L3.

🔬 In the Source
  • Short-term notepad: ga.py: do_update_working_checkpoint writes key_info / related_sop into self.working, then re-injects it via an "anchor prompt" each turn.
  • Long-term settlement: ga.py: do_start_long_term_update injects a distillation prompt that guides minimal file_patch updates to L2 facts, syncs the L1 index, and trims an L3 SOP when needed.
  • Settlement obeys the L0 iron rules: memory/memory_management_sop.md — only record "action-verified" info, never store volatile state, avoid overwrite and prefer small patches.
🧩 Analogy
Like doing experiments with a scratch pad at hand plus a lab notebook afterward: the scratch pad (working notepad) jots current points and gets wiped after each batch; only conclusions that were actually verified are carefully transcribed into the permanent notebook (long-term memory). Unverified guesses never make it in.
✅ Key Takeaways
  • Two memory tools: working_checkpoint (short-term, injected each turn) and start_long_term_update (long-term crystallization).
  • The iron rule: no execution, no memory — only crystallize verified information.
  • Write memory minimally: prefer small patches, never store volatile state.
💡 Design Insight
The iron rule "no execution, no memory" is what makes GA's memory trustworthy. A model's "inherent knowledge" and "reasoning guesses" may never be written as facts — only conclusions from genuinely successful tool calls deserve to crystallize into skills. This very principle keeps the memory store "more accurate the more you use it" rather than "dirtier", giving the later "self-evolution" skill tree a solid, repeatedly trustworthy foundation.
